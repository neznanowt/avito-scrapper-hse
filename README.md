# realty-scraper — сбор объявлений о квартирах (вторичка СПб)

Часть проекта центра по анализу рынка недвижимости: постоянный сбор объявлений с фото для оценки
состояния ремонта (репликация Almaas, Oust, Pollestad, 2026). Сейчас реализован **Авито**; Циан и Домклик
подключаются как новые адаптеры в `realty_scraper/platforms/` в ту же схему базы.

## Что делает

1. **Выдача.** Обходит поиск «вторичка, Санкт-Петербург», сортировка по дате. Авито отдаёт не больше
   100 страниц на запрос, поэтому запрос автоматически делится по ценовым диапазонам, пока каждая часть
   не уместится. Каждое появление объявления в выдаче — строка в `observations` (ежедневная панель цен).
2. **Карточки.** Для новых объявлений открывает страницу и разбирает встроенный JSON:
   - все поля из описания проекта, включая поле «ремонт», описание, координаты, метро;
   - ID дома Авито (для сравнения внутри дома);
   - тип продавца, просмотры;
   - полный список фото.
   Сырая страница сохраняется (`.html.gz`), её можно разобрать заново после правки парсера.
3. **Фото.** Скачивает фото, уменьшает до 384 px по длинной стороне. Для каждого фото считает SHA-1
   исходника (точные копии) и pHash (похожие фото — для поиска дубликатов и чужих фото).
4. **Пропавшие объявления.** После полного обхода выдачи помечает исчезнувшие (`missing_since`). Затем
   открывает их карточки и проверяет, сняты ли они (`status = closed/removed`). Это даёт срок экспозиции
   для расширения 7.

## Работа из Google Colab

Для команды есть ноутбук `notebooks/avito_collector_colab.ipynb`. Он позволяет:
- проверить парсер на живом сайте и провести пилот;
- дособрать данные после обрыва сессии;
- посмотреть таблицы и фото;
- сделать выгрузку для эконометристов и прогнать тесты.

Код ноутбук берёт из GitHub (`REPO_URL`) или из `realty-scraper.zip` в общей папке на Drive. Данные пишет в ту же папку.

Ограничения Colab, о которых нужно помнить:
- **Нет запуска по расписанию**, долгие сессии обрываются. Ежедневный сбор — основной результат проекта — должен работать на сервере или компьютере (раздел «Ежедневный режим»). Писать данные он может в ту же папку на Drive через Google Drive для компьютера.
- **IP-адреса Google.** Colab работает на серверах Google, в основном за пределами России, и Авито может их ограничивать. Это видно по ответу `probe`. Решение — прокси с российским IP (секрет `AVITO_PROXY`).
- **Место на Drive.** Бесплатных 15 ГБ хватит на пилот (~0,5 ГБ), но не на все фото (~18 ГБ).
- **База и профиль браузера** во время сессии лежат на локальном диске Colab (`/content`), потому что SQLite и Chrome плохо работают с файловой системой Drive. База копируется на Drive после каждой команды и каждые 10 минут. Если базу на Drive тем временем изменил кто-то другой, ваша версия сохраняется рядом как `realty_conflict_*.sqlite`, а общая не затирается.

## Установка

Нужен Python 3.10+ и Google Chrome (или встроенный Chromium Playwright).

```bash
git clone <репозиторий> realty-scraper && cd realty-scraper
python -m venv .venv && source .venv/bin/activate      # Windows: .venv\Scripts\activate
pip install -r requirements.txt
python -m playwright install chromium                  # если нет Google Chrome; тогда channel: null
cp config.example.yaml config.yaml                     # поменяйте seller_hash_salt
python -m realty_scraper init
```

На Linux-сервере без экрана дополнительно: `sudo apt install xvfb`. На Ubuntu Playwright может
попросить системные библиотеки: `python -m playwright install-deps chromium`.

## Первый запуск

```bash
python -m realty_scraper probe        # 3 страницы: проверка, что парсер видит выдачу, фильтр по цене и карточку
python -m realty_scraper pilot -n 500 # пилот: 500 свежих объявлений → карточки → фото → отчёт
```

`probe` печатает, какие поля карточки заполнились, и проверяет, работает ли фильтр по цене
(без него нарезка выдачи невозможна).

После пилота отчёт лежит в `data/reports/pilot_*.md`. В нём:
- заполненность полей;
- распределения поля «ремонт», типов продавцов и домов;
- число фото на объявление и размер файла;
- скорость сбора и прогноз объёма полного сбора и места под фото.

Пилот берёт **самые свежие** 500 объявлений (сортировка по дате). Для проверки парсера и оценки объёмов
это нормально, но это не случайная выборка.

## Ежедневный режим

```bash
python -m realty_scraper daily --budget-hours 7
```

Порядок шагов внутри запуска:
1. Вся выдача с нарезкой по цене (снимок цен и наличия).
2. Карточки новых объявлений, до 1500 за ночь.
3. Проверка пропавших из выдачи.
4. Обновление карточек старше 30 дней (просмотры, правки).
5. Фото.

Что не успели за 7 часов, продолжится в следующую ночь (код выхода 2).

**Первичный сбор** всех ~19 тыс. карточек при 7–16 с на страницу займёт несколько ночей. Точную оценку даст
отчёт пилота.

Расписание: `deploy/run_daily.sh` (запуск + резервная копия базы), а также
`deploy/realty-scraper.service` + `.timer` (systemd, 23:30 МСК) или `deploy/crontab.example`.

| Код выхода | Значение |
|---|---|
| 0 | успех |
| 1 | ошибка (подробности в `data/logs/`) |
| 2 | не уложились в лимит времени (продолжит завтра) |
| 3 | Авито заблокировал сбор |

### Все команды

| Команда | Что делает |
|---|---|
| `init` | создать папку данных и базу |
| `probe` | проверка на живом сайте |
| `pilot -n 500` | пилот с отчётом |
| `daily --budget-hours 7` | ежедневный запуск |
| `search [--max-cards N] [--no-slice]` | только выдача |
| `items --mode new\|refresh\|verify [--limit N]` | только карточки |
| `photos [--limit N]` | только фото |
| `reparse` | заново разобрать сохранённые страницы (после правки парсера) |
| `stats` | сводка: объявления, фото, последние запуски, ошибки |
| `report` | отчёт по всей базе (как у пилота) — если пилот шёл частями |
| `export [--out папка]` | `listings.csv` и `photos.csv` для коллег (UTF-8, открывается в Excel) |
| `backup [--keep 14]` | резервная копия базы в `data/backup/` |

## Блокировки

Страница считается блокировкой, если пришёл HTTP 403/429 или в ней фразы вроде «Доступ ограничен:
проблема с IP» вместо данных объявления. При блокировке:

1. Ошибка пишется в таблицу `errors`, скриншот сохраняется в `data/debug/`.
2. Сборщик ждёт 15 минут и пробует снова.
3. После третьей блокировки подряд запуск останавливается с кодом 3.

Капчи сборщик не проходит.
- Если поставить `wait_for_operator: true` и запускать с видимым браузером, он подождёт, пока проверку
  пройдёт человек.
- Профиль браузера с куки сохраняется в `data/browser_profile`.

Если блокировки станут регулярными:
1. Увеличьте паузы.
2. Запускайте с видимым браузером (`headless: false` + `xvfb-run`).
3. Попросите у центра прокси (`browser.proxy`).
4. Если это не поможет — план Б из описания проекта: выгрузка от площадки.

Непонятные страницы (не блокировка, но и не объявление) сохраняются в `data/debug/` для разбора.

## Данные

```
data/
  realty.sqlite                      база (описание полей — CODEBOOK.md)
  photos/avito/<id>/NN_<hash>.jpg    фото 384 px; L*.jpg — планировки
  raw/avito/items/<дата>/<id>.html.gz  сырые страницы карточек
  logs/  reports/  debug/  backup/  browser_profile/
```

Объём из описания проекта: 30 тыс. объявлений × 20 фото × ~30 КБ ≈ 18 ГБ фото. Сырые страницы занимают
порядка 100–150 КБ на карточку. Отключить их сохранение можно через `save_raw_items: false`.

## Правила сбора и персональные данные

- Один поток, пауза 7–16 с между страницами, длинные паузы, запуск ночью.
- Имена и телефоны продавцов **не сохраняются**. ID продавца хранится только как солёный хеш
  (`seller_key`): по нему можно сгруппировать объявления одного продавца, но нельзя узнать, кто это.
- Фото хранятся только на сервере центра и не публикуются; в работе — только агрегаты.

## Как устроен код

```
realty_scraper/
  cli.py, pipeline.py        команды и сценарии запуска
  browser.py                 Playwright: профиль, паузы, таймауты
  db.py                      схема SQLite и запись (новые колонки добавляются автоматически)
  photos.py                  скачивание, уменьшение, SHA-1, pHash
  report.py                  отчёт пилота
  platforms/avito/
    urls.py                  адреса выдачи
    parse_search.py          разбор выдачи (HTML-карточки + JSON-LD как запасной вариант)
    parse_item.py            разбор карточки (встроенный JSON + запасной разбор по HTML)
    crawler.py               обход: нарезка по цене, пагинация, блокировки
tests/                       pytest; test_integration.py гоняет весь конвейер на локальном «фальшивом Авито»
```

**Если Авито поменял вёрстку.**
1. `probe` покажет пустые поля, а `stats` — рост ошибок `parse_error` / `unexpected_page`.
2. Сохранённая страница из `data/debug/` — образец для правки `parse_item.py`.
3. После правки запустите `reparse`: он заново разберёт все сохранённые страницы без обращения к сайту.

**Новая площадка (Циан, Домклик).** Добавьте `platforms/<имя>/` с тем же набором функций: разбор выдачи и
карточки в `SearchCard` / `ParsedItem`, свой `crawler.py`. Таблицы общие, площадка различается колонкой
`platform`.

Тесты: `python -m pytest -q`.
